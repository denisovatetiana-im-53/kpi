# Аудит специфікації — Тетяна

## 1. Мета аудиту

Перевірити узгодженість вимог REQ-01–REQ-04, User Stories US-01–US-03, сценаріїв SC-01–SC-04 та варіантів використання онлайн-магазину.

## 2. Результати аудиту

| Об’єкт | Виявлена невідповідність | Рішення |
|---|---|---|
| REQ-01 / SC-01 | Потрібно перевіряти і назви, і поточні ціни товарів | Уточнено очікуваний результат SC-01 |
| REQ-02 / SC-02 | Не було явної перевірки ID замовлення та збереження ціни на момент оформлення | Уточнено критерії створення замовлення |
| REQ-03 / SC-03 | Не перевірялися всі недопустимі значення кількості | Додано нульову, від’ємну та дробову кількість |
| REQ-04 / SC-04 | Не було явної перевірки передавання ID замовлення та суми | Уточнено очікуваний результат сценарію |
| Актори / ER-модель | Buyer та Admin є ролями акторів, але не обов’язково окремими сутностями ER-моделі | Відмінність задокументовано у специфікації |

## 3. Перевірка узгодженості з ER-моделлю

- Замовлення має ідентифікатор і пов’язане з покупцем.
- Позиція замовлення зберігає товар, кількість і ціну на момент оформлення.
- Зміна поточної ціни товару не повинна змінювати збережену ціну в позиції замовлення.
- Облік залишків товарів виключено з меж поточної роботи.
- Ролі Buyer та Admin описуються як актори системи. Зміни ER-моделі не слід вносити без відповідної вимоги та обґрунтування.

## 4. Підсумок

Визначено три основні прогалини в початкових сценаріях: неповна перевірка створення замовлення, неповна перевірка некоректної кількості та відсутність явної перевірки даних запиту оплати. У підготовленій редакції специфікації ці пункти уточнено.

Статус: зміст аудиту підготовлено. Позначати виправлення як фактично завершені можна після перевірки відповідних файлів у репозиторії.
