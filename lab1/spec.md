# Specification — ER-модель онлайн-магазину

## Мета

Створити ER-модель онлайн-магазину для зберігання даних про
користувачів, товари, категорії, замовлення та платежі.

## Сутності та атрибути

### User
- id — унікальний ідентифікатор користувача
- name — ім'я користувача
- email — електронна пошта

### Category
- id — унікальний ідентифікатор категорії
- name — назва категорії

### Product
- id — унікальний ідентифікатор товару
- name — назва товару
- price — поточна ціна товару
- category_id — категорія товару

### Order
- id — унікальний ідентифікатор замовлення
- user_id — користувач, який створив замовлення
- created_at — дата та час створення замовлення

### OrderItem
- id — унікальний ідентифікатор позиції замовлення
- order_id — замовлення
- product_id — товар
- quantity — кількість товару
- unit_price — ціна одиниці товару на момент замовлення

### Payment
- id — унікальний ідентифікатор платежу
- order_id — замовлення
- amount — сума платежу
- status — статус платежу

## Зв'язки

- Один User може мати багато Order.
- Кожен Order належить одному User.
- Одна Category може містити багато Product.
- Кожен Product належить одній Category.
- Один Order містить одну або багато OrderItem.
- Кожен OrderItem належить одному Order.
- Один Product може входити до багатьох OrderItem.
- Кожен Order має один Payment.
- Кожен Payment належить одному Order.

## Критерії прийняття

1. Кожна сутність має первинний ключ id.
2. Первинні та зовнішні ключі використовують узгоджений тип int.
3. Кардинальності зв'язків відповідають опису предметної області.
4. Зв'язок між Order і Product реалізовано через OrderItem, оскільки цей зв'язок має власні атрибути quantity та unit_price.
5. Назви сутностей та атрибутів у ER-моделі відповідають цій специфікації.
6. Модель не містить дубльованих даних, які можна винести в окремі сутності.
